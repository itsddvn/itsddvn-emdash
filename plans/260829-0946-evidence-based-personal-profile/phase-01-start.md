# Phase 1: Profile evidence contract

## Outcome

Lock the current, publishable truth before creating another mockup or changing source code.

## Inputs

- [Cross-project profile evidence](./research/cross-project-profile-evidence.md)
- [Project portfolio audit](./research/project-portfolio-audit.md)
- Current site content and production routes
- User-provided current facts and privacy choices

## Requirements

- Confirm public name, current role/title, organization relationship, city/location, and short bio.
- Confirm which contact and social channels remain current.
- Mark project/client/company details as public, anonymized, or private.
- Approve or revise the Builder–Operator–Codifier position.
- Approve Vietnamese-first voice and Build → Operate → Codify labels.
- Do not copy archived phone, email, role, or location into production without confirmation.

## Steps

1. Present a compact fact sheet with archived values marked **stale until confirmed**.
2. Ask one material question at a time.
3. Record approved wording in a profile content brief.
4. Record claims that must not appear publicly.
5. Define a one-sentence Vietnamese position and equivalent English position.
6. Stop for explicit user approval.

## Deliverables

- `research/profile-content-brief.md`
- approved public/private boundary table
- approved Vietnamese and English one-line position

## Success criteria

- [x] Every identity field is confirmed or intentionally omitted.
- [x] No inferred personality claim is represented as biography fact.
- [x] Builder–Operator–Codifier narrative is approved.
- [x] Privacy boundary covers clients, companies, metrics, contact, and photographs.
- [x] User explicitly unlocks Phase 2.
