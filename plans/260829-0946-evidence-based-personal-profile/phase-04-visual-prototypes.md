# Phase 4: Visual prototypes

## Outcome

Approve a desktop/mobile visual system built from real portrait, project imagery, and evidence—not a generic AI persona.

## Aesthetic thesis

**Founder Operating System:** dark, modular, confident, and evidence-led. The visual character borrows Zelio's dense framed composition and decisive contrast, but replaces developer-terminal cues with company-building systems, operating decisions, and CEO accountability. CPPAI-inspired orange and earth-brown connect Build, Operate, and Codify across the page.

## Requirements

- Preserve one CPPAI-inspired orange accent family over earth-brown surfaces; no blue or neon secondary palette.
- Make the above-the-fold identity unmistakably CEO and builder, not freelance developer.
- Do not use tech-stack logos, code syntax, CV downloads, experience counters, client counts, or unverified vanity metrics as identity furniture.
- Limit the homepage to five core panels: identity, operating method, selected systems, writing, and contact.
- Use one restrained type scale: 12px labels, 16–18px body, 20–32px card titles, 32–40px section titles, and 44–56px hero title.
- Use approved portrait and project assets only.
- Portrait capabilities render as a six-axis spider chart. Each polygon vertex radius is calibrated from the user-supplied percentage, making strengths and weaknesses visible; fixed outer labels show the exact values. `Nước nói` remains the only filled, animated badge.
- Prototype Operating Atlas with real nodes and links.
- Section transitions use transform and opacity only: 180ms exits and 320ms entrances. System diagrams use one traveling signal and one restrained core ring; all motion stops under reduced motion.
- Provide keyboard, touch, reduced-motion, and no-JavaScript states.
- Keep supporting pages visually coherent but quieter than the homepage.
- Preserve the existing desktop three-column article reading experience.
- Article pages preserve the desktop meta/content/gutter structure while using a 44–56px article title, 26–30px section headings, 17–20px reading text, and responsive metadata/gutter layouts.
- Do not modify `src/` before explicit approval.

## Steps

1. Create a content-first grayscale wireframe.
2. Verify hierarchy with all animation disabled.
3. Create two distinct art directions using the same approved content.
4. Compare them against the evidence report, not generic portfolio trends.
5. Build one functional HTML prototype for the selected direction.
6. Browser-test desktop/mobile, keyboard, touch, and reduced motion.
7. Remove decorative motion that does not communicate evidence.
8. Stop for explicit user approval.

## Success criteria

- [ ] Design is recognizable from real work graph and voice even without the logo.
- [ ] Homepage is not mistaken for a blog, agency, SaaS, or generic AI portfolio.
- [ ] Operating Atlas remains clear with motion disabled.
- [ ] Mobile is a deliberate linear composition, not a collapsed desktop canvas.
- [ ] User explicitly unlocks source implementation.
